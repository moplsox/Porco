# 美术资产、v2重做范围与来源

本轮v2重做的是三人的角色立绘与12张事件CG。人物的脸型、五官关系、身材和衣型，以用户提供的电影原图参考PDF为准；先做每套服装的中性基准，再由同一基准生成表情差分。事件CG依据这些人物锚点重新构图，表现本作剧本中的具体动作与场景。

本轮没有重做10张无人物主背景，22张夜景／雨景SVG仍是上一版的原创临时插画。不能把本次修改描述成“全部美术重新绘制”，也不能声称生成角色与电影原画逐像素一致。下文登记v2的交付结构和审阅要求；并行生成收尾与最终核实状态见文末。

## v2角色立绘结构

统一表情名为 `neutral / smile / serious / sad / surprise / tired`。每一套服装先锁定中性基准，后续只对眉、口、嘴角等作小幅变化，保持头身比例、配饰、服装与主要站姿一致。平涂主色、硬边赛璐璐阴影和深黑棕细轮廓线为人物方向；不以3D体积光、厚涂或水彩纸纹重设计角色。

吉娜的 `work × 6表情` 是 `morning × 6表情` 的运行别名，指向同一套深蓝水手领日装，不另外生成或计作6张独立图。因此，v2应为**42张独立角色PNG、48个角色资源槽位**。独立素材与别名槽位必须分开统计，不能把48槽位都称为独立立绘。

角色源PNG使用透明背景。文件命名采用 `portrait-{角色}-{服装}-{表情}.png`，具体活动路径以 `assets/manifest.json` 为准；封装后可由清单指向对应的无损WebP。旧SVG角色稿不再计作v2正式立绘。

## 透明检查与无损封装

透明PNG可能在alpha为0的区域保留隐藏RGB。某些直接图片预览会把这些隐藏色显示成灰褐光晕，不能仅凭这种预览就判断游戏里存在背景或光晕。角色检查需要把图像按alpha正确合成到实际背景，并另用浅底、深底复核轮廓；同时检查半透明边缘、内部不透明度、黑胡须与服装颜色。

交付封装可采用**无损WebP**，剔除alpha=0像素中无显示意义的隐藏RGB；该操作必须保持alpha通道及所有可见像素不变，不修改半透明边缘的颜色。不能把清除隐藏RGB写成“重绘角色”或“修复可见光晕”，也不能用有损压缩掩盖线条与透明边缘问题。生成PNG原件保留，最终运行格式和路径由活动清单登记。
